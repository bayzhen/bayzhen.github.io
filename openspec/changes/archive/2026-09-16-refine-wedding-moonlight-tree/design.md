## Context

现有树木已经使用 520×700 的内联 SVG、三层树冠和基于阶段 class 的 CSS 动画；照片相框与花苞、星星共用同一树冠区域。精修必须沿用当前坐标系和互动位置，避免重新校准游戏逻辑，也不能引入会增加首屏请求的新图像依赖。

## Goals / Non-Goals

**Goals:**

- 让树干、根系、枝梢、叶片和花朵从“规则图标组合”提升为具有插画深度的有机整体。
- 让新增细节与树干生长、树冠展开、花开和微风动画保持一致。
- 控制 SVG 节点量、滤镜范围和移动端装饰密度，维持顺畅的单屏体验。

**Non-Goals:**

- 不改变种树、滑动、花苞、星星、照片回看与邀请函的流程或点击坐标。
- 不增加 Canvas 绘树、WebGL、三维视角或外部插画资源。
- 不修改婚礼信息、照片内容、音乐和分享卡片。

## Decisions

1. **继续使用语义分组的内联 SVG。** 在现有定义中加入单叶、复叶、花苞和小花符号，再以远景枝影、主体枝干、树皮刻线、三层叶组和前景饰叶分组复用。这样能复用阶段动画并保持轮廓清晰；相比位图插画，也不会损失高分屏清晰度。
2. **用“底层阴影描边 + 主体渐变描边 + 少量高光刻线”塑造树干。** 阴影描边提供体积，主体路径继续承担生长动画，刻线延迟显现。避免复杂 SVG 纹理滤镜，以降低移动端合成成本。
3. **让树冠由不同植物形态而不只是同一枝叶符号组成。** 保留复叶枝，新增独立椭圆叶、细长叶和小圆叶枝；远景使用低对比大形态，前景使用较少的月光边缘叶，中央留出相框和星星的视觉空间。
4. **花朵包含盛放、半开和花苞三种状态。** 三个叙事区域各自使用不同尺度与朝向，仍由原有三组阶段 class 控制，避免更改 JavaScript。
5. **高光细节采用低透明度并受阶段控制。** 叶脉、露珠和轮廓光仅在树冠展开后可见，窄屏降低部分密度，减少动态偏好下关闭呼吸与闪烁动画。

## Risks / Trade-offs

- [更多 SVG 节点可能增加低端手机绘制成本] → 大量细节通过 `<use>` 复用，限制模糊滤镜数量，并在窄屏隐藏最次要的点状装饰。
- [新增前景叶片可能遮住相框或操作按钮] → 保持中央三处相框周围留白，并让所有树木图层继续位于互动控件下方。
- [精细线条在小屏缩放后不可见] → 将细节用于整体质感而非承载信息，关键轮廓使用足够宽的描边和色差。

## Migration Plan

直接替换婚礼页 SVG 树形与对应样式，更新静态资源版本号后构建发布。若出现性能或布局回归，可单独回退 HTML/CSS 提交，游戏状态和数据无需迁移。
