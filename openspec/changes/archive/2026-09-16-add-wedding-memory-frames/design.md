## Context

月光花树已经具备固定单屏布局、分阶段状态机、三个花苞、三颗落星、粒子效果和可退出邀请函。照片目录包含九组小图与高清 WebP；主页当前仅直接使用星光合照背景和黑色礼服邀请卡背景。

## Goals / Non-Goals

**Goals:**

- 让全部九组现有照片参与花树叙事，而不是添加独立相册或轮播页。
- 让三组相框成为树冠中的持久视觉元素，并在花苞与落星阶段体现正反面关系。
- 仅在照片进入流程时加载相应资源，保持微信首屏负担可控。
- 保持当前单屏游戏、手势、音乐、邀请信息和分享元数据不变。

**Non-Goals:**

- 不重新处理、裁切或生成照片，不增加外部图片服务。
- 不要求访客逐张关闭照片才能完成游戏，也不增加限时操作。
- 不修改三个长版概念页。
- 本次不创建文章系列，素材均来自仓库，不涉及外部来源新鲜度。

## Decisions

### 三组双面悬挂相框映射全部记忆照片

- 左侧相遇相框：正面为 `orange-playful`，背面为 `orange-portrait`。
- 中间相知相框：正面为 `veil-closeup`，背面为 `starlight-bride` 与 `black-suit-groom` 双联肖像。
- 右侧相守相框：正面为 `traditional-closeup`，背面为 `traditional-portrait`。
- `starlight-couple` 继续作为页面背景，`black-gown-couple` 继续作为邀请卡背景。

这使九组照片都有唯一的主要叙事位置。替代方案是频繁更换整页背景，但会破坏树和文字的对比度，也更容易造成强烈闪动。

### 展开视图与树上缩略框分离

树上相框只加载 `-small.webp` 作为缩略图；点击花苞或落星时，单独的记忆展开层根据映射填充响应式 `srcset`。展开层自动收拢但始终提供关闭按钮，游戏完成后再点击相框则保持展开，并提供“翻看另一面”。

### 用 `data-src` 保证渐进加载

未进入流程的缩略图只保存 `data-src`，没有 `src` 或 `srcset`。JavaScript 在对应花苞或落星触发时才填充缩略图和展开视图；重玩时恢复视觉状态，但已经由浏览器缓存的图片无需强制重新下载。

### 记忆展开不成为新的页面状态

记忆层是覆盖在同一互动区域上的临时展示，不修改主状态机顺序。它拦截短暂点击，自动关闭后访客继续当前阶段；直接查看邀请会立即关闭记忆层并优先显示邀请函。

## Risks / Trade-offs

- [相框与现有花苞或落星重叠] → 将相框固定在树冠中上部，星星保留在中下部，并分别为桌面和手机设置位置。
- [双联肖像在手机上过小] → 展开时使用并排画面，树上缩略图只作为可识别的双格装饰。
- [连续快速触发导致展开内容覆盖] → 展开层接管指针事件并集中管理单一关闭计时器。
- [高清资源影响流量] → 缩略框只请求小图，展开视图通过 `srcset` 由浏览器选择，并且按互动顺序加载。
- [自动收拢影响阅读] → 正常流程停留足够时间，用户可主动关闭；完成后的回看模式不自动收拢。

## Migration Plan

1. 在主页加入三个双面相框和一个复用的记忆展开层，更新静态资源版本号。
2. 为相框种下、翻面、展开、双联和窄屏布局增加样式。
3. 将照片映射与渐进加载接入花苞、落星、完成、直接查看和重玩流程。
4. 验证九组图片映射、网络加载时机、完整交互、窄屏布局和生产构建。
5. 提交推送并验证 GitHub Pages 后同步归档规范；回滚可恢复本次提交前的三个主页文件。
