## Context

婚礼主页目前由内联 SVG、CSS 动画和原生 JavaScript 状态机组成，并与通用背景音乐入口和固定邀请卡共存。现有树只包含少量线条、椭圆叶片和三维旋转变量；本次继续采用无依赖的静态实现，但替换树的图形结构和交互状态。

## Goals / Non-Goals

**Goals:**

- 在不引入框架或大型图片下载的前提下，让花树拥有明显更丰富的插画层次。
- 让所有手势都能通过一次宽容的方向判断完成，并有按钮和键盘替代方式。
- 保持单屏、现有音乐入口、婚礼信息、分享元数据及邀请卡能力。
- 在微信常见窄屏和短屏上稳定运行。

**Non-Goals:**

- 不实现真实三维模型、陀螺仪、物理引擎或限时玩法。
- 不新增个人信息、照片或第三方网络依赖。
- 不改造另外三个长版婚礼概念页。
- 本次不创建文章系列，也不存在来源时效或补丁新鲜度问题。

## Decisions

### 使用分层内联 SVG，而不是生成一张完整树图

树由填充式树干、细枝、后景树影、三组树冠、重复的手绘叶簇、花簇和高光组成。SVG 分组允许树干、树冠和花朵分别生长，也能用较小资源获得清晰的高像素密度显示。

替代方案是使用一张透明 PNG 插画，但它难以自然地分阶段生长，并会增加下载尺寸；继续在旧树上增加椭圆叶片也无法解决几何感过强的问题。

### 用二维摇曳替代三维旋转

上滑阶段仅根据纵向位移判断，摇树阶段仅根据横向位移判断。横向动作触发一次预设的树冠与枝干摆动动画，随后星星沿固定路径落到可见终点，不再把拖动距离映射成观察角度。

替代方案是保留轻量视差或陀螺仪，但仍需要用户理解空间关系，且微信 WebView 行为更难预测。

### 每个手势都提供显式按钮

树冠阶段展示“向上滑动 · 或轻触生长”，摇树阶段展示“左右轻划 · 或轻触摇树”。按钮与手势调用同一状态转换，键盘方向键也可以触发。

### 花苞按顺序激活，星星可任意顺序点击

三处花苞同时保留轮廓，但只有当前目标强光提示，减少访客判断成本；星星落下后全部可见并永久停留，避免形成反应速度游戏。

### 保留单一状态机并增加可取消计时器

状态顺序为 `seed → trunk → canopy → bloom → shake → stars → complete`。所有延迟转换都集中记录，在直接查看或重新体验时取消，避免旧计时器改变新状态。

## Risks / Trade-offs

- [大量 SVG 元素可能增加移动端绘制成本] → 复用叶簇符号、限制滤镜范围，并在减少动态偏好和短屏下压缩动画。
- [用户可能不知道从哪里滑动] → 整个树互动区域均接受手势，并提供带方向图标的固定提示按钮。
- [花树过密可能遮住背景人物或标题] → 树冠集中于中下区域，使用半透明深色后景和有限高光控制对比度。
- [左右轻划可能被误认为页面导航] → 页面本身无横向导航，互动区域设置 `touch-action: none`，并要求明确横向位移后才触发。
- [小屏邀请卡内容拥挤] → 延续短屏紧凑排版，并以 320×568 作为最低回归尺寸。

## Migration Plan

1. 替换主页树的 SVG 分组和互动控件，不改变页面 URL、音乐文件或分享元数据。
2. 更新 CSS 状态动画与 JavaScript 状态机，移除旋转角度和隐藏星星逻辑。
3. 通过脚本语法检查、OpenSpec 验证、Jekyll 构建和浏览器自动交互验证。
4. 提交并推送后校验 GitHub Pages 资源哈希；如需回滚，可恢复前一提交中的三个主页文件。
