## 一、变更目标

本次实现核心是给影响力图增加一套“回放/调试查看”能力，重点服务直塞球影响力图与直塞选点过程：

1. 在 `AIDebugPanel` 新增“影响力图回放查看”功能入口。
2. 支持查看普通影响力图矩阵：如 `NormalPassInfluenceMap`、`InterceptInfluenceMap`、`RunPosInfluenceMap`、`StraightPassInfluenceMap` 等。
3. 支持按选中球员过滤并重绘该球员对应的 source。
4. 支持直塞选点 cluster 可视化：候选点、最优点、传球耗时、拦截信息等。
5. 支持主动重算影响力图结果，方便固定传球人、接球人、起点做复现。
6. 在 C++/Python 直塞链路埋点，追踪输入、选点、踢球、轨迹创建等关键节点。

## 三、整体架构

```text
AIDebugPanel
  ├─ InfMapDebugDataProvider
  │   ├─ 普通图：读取 inf_map.get_all_data()
  │   ├─ 选中球员 source：读取 debug_get_gizmos_source_info() / source_info_dict
  │   ├─ 直塞 cluster：读取 PassAnimData.through_point_cluster
  │   └─ 主动重算：调用 NormalPass / StraightPass debug API
  │
  └─ InfMapRenderer
      ├─ QuickGUI 输出文字信息
      ├─ QuickGizmos 绘制 107x69 矩阵热力图
      └─ QuickGizmos 绘制直塞候选点/最佳点

StraightPassInfluenceMap(C++)
  ├─ debug_enable_gizmos()
  ├─ debug_get_intermediate_map(name)
  ├─ debug_get_intermediate_map_names()
  ├─ debug_get_gizmos_source_info()
  ├─ debug_get_select_points()
  ├─ debug_get_ball_pos()
  └─ debug_get_*_source()
```

核心思想：

- C++/Python 影响力图继续负责计算。
- 新增 Provider 做数据整理，不直接耦合 UI 绘制。
- 新增 Renderer 做展示，不关心数据来源。
- DebugPanel 只负责用户选择参数、触发 Provider、调用 Renderer。

## 四、DebugPanel 功能

`AIDebugPanel.py` 新增 `FunctionType.inf_map_replay = 48`，名称为“影响力图回放查看”。面板内部维护以下状态：

- 当前图名：`inf_map_replay_map_index`
- 当前队伍：`inf_map_replay_team_index`
- 当前模式：`inf_map_replay_mode_index`
- 当前 ViewModel：`inf_map_replay_view_model`
- 主动重算配置：传球人、接球人、起点、间隔帧、`need_predict`

支持图名：

```python
NormalPassInfluenceMap
InterceptInfluenceMap
RunPosInfluenceMap
DefenceRangeComposableInfluenceMap
StraightPassInfluenceMap
PassValueInfMap
```

支持模式：

1. **普通图**：直接显示整张影响力图矩阵。
2. **选中球员source**：只显示选中球员对应的 source 贡献。
3. **直塞cluster查看**：显示直塞候选点 cluster，而不是矩阵。

## 五、数据提供层：InfMapDebugDataProvider

`InfMapDebugDataProvider` 统一把不同来源转换成 `InfMapViewModel`。

### 1. 普通图模式

流程：

```text
图名 + 队伍
  -> 拼成 map_name，例如 StraightPassInfluenceMap_0
  -> black_box.get_map_by_name(map_name)
  -> inf_map.get_all_data()
  -> InfMapViewModel(width=107, height=69, data, min, max)
```

异常情况会返回错误 ViewModel，比如“影响力图不存在”“数据为空”“尺寸不匹配”。

### 2. 选中球员 source 模式

流程：

```text
选中球员 eid
  -> InfMapDebugPlayerIdentity 生成 eid/eid_info token
  -> 优先读取 inf_map.debug_get_gizmos_source_info()
  -> 回退读取 inf_map.source_info_dict
  -> 用 source_key 匹配球员 token
  -> 将匹配 source 加到 GizmosInfluenceMap
  -> 返回 GizmosInfluenceMap.get_all_data()
```

匹配规则：

- `source_key == token`
- `source_key.startswith(token + "_")`
- `source_key.endswith("_" + token)`
- `source_key.endswith(token)`

这让 C++ debug source 与 Python `source_info_dict` 两种格式都能复用。

### 3. 直塞 cluster 模式

流程：

```text
当前队伍
  -> 优先取 current_commander_player_eid
  -> 读取 player.logic_core.hotfix_mgr.get_pass_anim_data_ref()
  -> 读取 pass_data.through_point_cluster
  -> 读取 pass_data.target_pos 作为最佳点
  -> 输出候选点、最佳分、传球时间、近距离拦截信息
```

该模式不绘制矩阵，而是绘制空间点：

- 白色球：候选直塞点。
- 黄色球：与 best_point 近似重合的候选点。
- 红色球：最终落点/最佳点。

### 4. 主动重算

面板打开“主动重算”后，Provider 会按间隔帧触发重算：

- 普通传球图：调用 `NormalPassInfluenceMap.get_normal_pass_position()`。
- 直塞图/cluster：调用 `StraightPassInfluenceMap.get_random_straight_pass_position()`。

可配置：

- 传球人：持球人 / 当前操控球员 / 左侧选中球员 / 下方指定球员。
- 接球人：左侧选中球员 / 当前操控球员 / 下方指定球员。
- 起点：球位置 / 传球人位置。
- 是否 `need_predict`。
- 重算间隔帧。

## 六、渲染层：InfMapRenderer

`InfMapRenderer` 职责很单纯：拿 `InfMapViewModel` 画 UI 与 Gizmos。

### 1. 矩阵热力图

普通影响力图满足以下条件才绘制：

- `view_model.error is None`
- `view_model.data` 非空
- `width * height == len(data)`

绘制流程：

```text
QuickGizmos.register_static_matrix_profile(width, height)
QuickGizmos.draw_static_matrix(data, max, min)
```

默认缩放：`0.2`。

同时会绘制一个颜色条 `inf_map_replay_color_converter_view`，帮助观察热力图颜色映射。

### 2. 直塞 cluster 点

如果 `view_model.points` 存在，则不画矩阵，改为画候选点：

- 候选点半径 `0.18`。
- 最佳候选点半径 `0.35`。
- 最终 best_point 半径 `0.45`。

## 十、直塞影响力图可视化 Helper 调整

`StraightPassInfluenceMapVisualizationComponent` 新增：

```python
def enable_debug_capture(self):
    InfMapDebugCaptureController(self.black_box).enable_straight_intermediate_capture(self.team_index)
```

`matrix_gizmos_data_source()` 每次取数据前调用 `enable_debug_capture()`，确保：

- C++ 图调用 `debug_enable_gizmos()`。
- Python 图设置 `ENABLE_INTERMEDIATE_DEBUG = True`。

随后优先读取 C++ debug 中间图：

```python
intermediate_map_data = self.debug_get_intermediate_map(intermediate_map)
if intermediate_map_data:
    return intermediate_map_data
return self.get_all_data()
```

这样直塞 C++ 化后，旧的 Python `_inter_map_data` 不再是唯一来源。

## 十一、Python 版 StraightPassInfluenceMap 调试补强

`StraightPassInfluenceMap.py` 中新增多处 `[InfMapReplayDebugPY]` 日志：

- 中间图未开启时 `record_skip`

这些主要用于兼容/对比 Python 版直塞图逻辑，确认 C++/Python 两条链路调试数据是否一致。

## 十二、使用流程

1. 打开 AI Debug Panel。
2. 选择功能：“影响力图回放查看”。
3. 选择图名与队伍。
4. 选择模式：
   - 普通图：看整张图热力图。
   - 选中球员source：左侧选中球员后看该球员 source。
   - 直塞cluster查看：看直塞候选点与最佳点。
5. 如需复现固定场景，勾选“主动重算”：
   - 设置重算间隔帧。
   - 选择传球人/接球人来源。
   - 选择起点/瞄准点。
   - 配置 `need_predict`。
6. 观察矩阵、候选点、文本信息与日志。

## 十三、当前实现特点

1. **数据与绘制解耦**：Provider 负责组装 ViewModel，Renderer 负责绘制。
2. **兼容 C++/Python 图**：source 读取优先走 C++ debug API，失败回退 Python `source_info_dict`。
3. **支持直塞 C++ 化后调试**：新增 C++ 中间图名称获取与中间图数据读取能力。
4. **可主动重算**：不用等真实输入触发，可在面板中固定传球人/接球人重算。
5. **链路日志完整**：从输入层到动画/逻辑层，再到 C++ pass state/operation，都有 trace。

## 十五、简要结论

本次实现不是新增一张影响力图，而是为影响力图系统新增“回放与调试可视化能力”。核心落点是直塞球：通过 C++ debug API 暴露直塞影响力图中间矩阵、source、候选点与 cluster 数据，再由 Python 面板统一展示，并辅以主动重算与全链路 trace，解决直塞选点问题难复现、难观察、难定位的问题。
