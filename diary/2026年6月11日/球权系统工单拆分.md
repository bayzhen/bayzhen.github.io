# 球权系统 —— 工单拆分建议

> 整理日期：2026-06-11

## 二、依赖关系与并行度

```
T1 三态底座 ──┬─→ T2 预测解耦 ──┬─→ T3 UNOWNED 接线 ──→ T6 执行层
              │                  └─→ T7 球速子条件C
              ├─→ T4 缓冲累积器 ──→ T5 Situation 挂起+重定向
              └──────────────────────────────────────→ T6
```

- **第 1 波（无依赖）**：T1
- **第 2 波（可并行）**：T2、T4（分属预测层 C++ 与球权层 Python，互不阻塞）
- **第 3 波**：T3（待 T2）、T5（待 T4）
- **第 4 波**：T6（待 T1+T3）、T7（待 T2，可与 T6 并行）

→ 关键路径：T1 → T2 → T3 → T6（4 单串行），其余挂边并行。

---

## 三、为什么是这个粒度

| 决策 | 理由 |
|---|---|
| T2 与 T3 拆开 | T2 是纯重构（行为不变、可单测），T3 才改变 UNOWNED 行为；拆开后 T2 出问题易隔离 |
| T7 独立 | 球速子条件 C 真身**完全不存在**，是净新增且需定阈值，与 T2 重构风险性质不同，单独成单避免互相污染验收 |
| T4 早做、与 T2 并行 | 缓冲累积器只读球权状态、不依赖预测层，可与 C++ 侧并行推进，压缩周期 |
| T5 绑 T4 不绑 T3 | Situation 消费的是"稳定球权"（T4 产出），不是瞬时 UNOWNED；绑 T4 依赖更准 |
| T6 放最后 | 执行层表现依赖底层三态 + UNOWNED 已打通，否则无法验收 HR 行为 |
| T8 不进本期 | R5 是 P1 草案，机制未定，强行排期会阻塞 P0 |

## 四、各单验收口径（对齐设计 §十三）

| 单号 | 验收标准 |
|---|---|
| T1 | Task/HR/InfluenceMap 搜 `ControlStage` 零命中；调试工具 UNOWNED 三态可见 |
| T2 | 重构前后行为一致（回归）；长传/直塞 `has_clear_winner=True` 时进攻 Task 不中断 |
| T3 | Case 2 进 UNOWNED；Case 3/5/7 期间非追球人 HR 不切换；UNOWNED 不超 MAX 帧 |
| T4 | 反复抢断 `ball_ownership_stable` 不翻转；短暂失球拿回（< N 帧）不触发翻转 |
| T5 | 反复抢断 Situation 不频繁重竞标；短暂失球拿回当前 Situation 延续 |
| T6 | Case 3/5/7 非追球人 HR 点位不切换；GK 在 UNOWNED 正常出击扑球；HR 切换无瞬跳 |
| T7 | 高速直塞场景按球速正确判定 winner / 维持 UNOWNED |
