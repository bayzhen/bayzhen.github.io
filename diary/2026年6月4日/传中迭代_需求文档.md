# 传中迭代需求文档

## 1. 需求概述

### 1.1 需求名称

手操传中系统迭代——球追人方案

### 1.2 需求背景

当前手操传中存在明显随机感：玩家蓄力后无法预期球会传给谁、落到哪里、以什么弧线飞行。接球人经常无法提前到位，传中球容易飞到无人区；守门员出击又几乎必胜，导致传中很难成为稳定有效的进攻手段。

### 1.3 需求等级

A 级。

理由：传中是足球比赛核心进攻方式之一，影响边路进攻、禁区争顶、头球射门、守门员出击、防守博弈等多条核心链路。

### 1.4 上线赛季

待定。

### 1.5 文档版本

v1.0，待评审。

### 1.6 设计路径

球追人（Path A）。

核心原则：踢球帧完成所有决策，球的轨迹固定，接球人自然到位。

## 2. 问题定义

### 2.1 问题一：传中目标随机感强

#### 现象

- 蓄力时长不影响落点区域。
- 蓄力时长不影响弧线参数。
- 三档传中弧线视觉差异极小。
- 玩家松手后不知道传给谁。
- 玩家操作意图与传中结果严重脱节。

#### 影响

- 玩家认为传中不可控。
- 蓄力操作缺少意义。
- 高手无法用传中做稳定战术选择。

### 2.2 问题二：传中球飞到无人区

#### 现象

- 落点基于接球人当前位置计算，不预测移动。
- 退化兜底找到的落点不保证接球人能跑到。
- 球飞行中 AI 接球规则持续运行，接球人可能被重新分配任务，离开落点。

#### 影响

- 传中失败原因不可理解。
- 接球成功率不稳定。
- 玩家觉得系统“传歪”或“没人接”。

### 2.3 问题三：接球动作生硬

#### 现象

- 接球人跑位目标每帧由 AI 规则更新。
- 踢球帧没有锁定目标。
- 初期路径混乱，偶尔停步等待。
- 三档传中弧高不同，但接球动画没有对应高度档位。
- 动画高度和球实际到达高度不匹配。

#### 影响

- 传中接球表现不顺。
- 争顶、胸停、脚接等动作切换生硬。
- 进攻节奏被打断。

### 2.4 问题四：守门员出击必胜

#### 现象

- 出击判定只比较“守门员到达帧 ≤ 接球人到达帧”。
- 不考虑接球人的争顶能力。
- 传中拦截特质只扩大出击区域。
- 传中几乎无法转化为实质威胁。

#### 影响

- 守门员出击缺少真实博弈。
- 高头球、高弹跳前锋价值不明显。
- 传中进攻收益过低。

## 3. 设计目标

### 3.1 目标一：蓄力操作与传中结果强相关

短按、中按、长按需要稳定映射到不同传中意图：

- 短按：近柱低弧快球。
- 中按：中路标准弧线球。
- 长按：远柱高弧慢球。

玩家在松手前应能看到预期目标高亮，并通过视觉、振动感知档位变化。

### 3.2 目标二：传中球稳定落到接球人附近

落点应基于接球人未来预测位置，而不是当前位置。接球人需要在踢球帧被锁定，避免被 AI 任务打断。

### 3.3 目标三：接球过程流畅，动画高度匹配

接球人从踢球帧开始按预测路径跑动，并根据球到达高度提前切换接球准备动作。

三档传中应对应不同高度的接球动画候选集。

### 3.4 目标四：守门员出击有真实博弈

守门员出击不能只看谁先到，应结合：

- 守门员到位时间
- 接球人到位时间
- 接球人争顶属性
- 守门员能力
- 球到达高度和位置

## 4. 方案总览

采用球追人方案：踢球帧一次性完成全链路决策，生成固定轨迹，接球人按预测位置跑动。

整体流程：

```text
玩家蓄力松手
→ M1 意图识别
→ M2 候选人筛选
→ M3 未来位置预测
→ M4 接球人锁定
→ M5 落点计算
→ M6 飞行风格映射
→ M7 球的飞行
→ M8 接球人奔跑到位
→ M9 异常兜底
→ M10 守门员出击
→ M11 玩家实时反馈
```

## 5. 功能需求

### 5.1 M1：玩家意图识别

#### 优先级

P0

#### 需求描述

系统需要在玩家按下传中键后记录蓄力时长，并结合摇杆方向生成“传中意图”。

#### 规则

| 输入 | 档位 | 传中意图 |
| --- | --- | --- |
| 蓄力 `<0.3s` | 近柱档 | 低弧、快速、短滞空 |
| 蓄力 `0.3~0.7s` | 中路档 | 标准弧线、中速 |
| 蓄力 `>0.7s` | 远柱档 | 高弧、中低速、长滞空 |

摇杆方向参与目标偏向计算。冲刺状态下摇杆方向置零，避免输入冲突。

#### 输出

`CrossIntent`，建议包含：

- 蓄力时长
- 蓄力档位
- 摇杆方向
- 是否冲刺
- 传中发起帧
- 传中球员 ID

#### 验收标准

- 不同蓄力时长能稳定映射到不同档位。
- 档位可被后续候选筛选、落点计算、飞行风格模块读取。
- 帧同步下结果确定。

### 5.2 M2：候选人筛选

#### 优先级

P0

#### 需求描述

系统根据传中意图，从进攻方球员中筛选 Top-3 接球候选人。

#### 评分维度

- 动态归属度：球员是否能在球到达时跑到落点附近。
- 摇杆偏向：是否符合玩家方向输入。
- 可达性：移动能力和预计到位时间。
- 越位软扣分：越位风险越高，评分越低。
- 争顶能力：头球、弹跳、身高、身体对抗等。

#### 输出

- Top-1 主接球人。
- Top-2/Top-3 次选接球人。
- 每个候选人的评分和可达信息。

#### 验收标准

- 短按更倾向近柱候选人。
- 长按更倾向远柱候选人。
- 摇杆方向能明显影响候选排序。
- Top-3 候选均具备基本可达性。

### 5.3 M3：未来位置预测

#### 优先级

P0

#### 需求描述

系统需要预测候选人在球到达时的位置，并输出预测高度和置信度。

#### 预测规则

- 飞行时间 `<0.5s`：使用简单预测。
- 飞行时间 `≥0.5s`：使用增强预测，并加入防守修正。
- 根据球员速度、加速度、当前朝向、目标方向画可达圆。
- 预测点必须通过可达性验证。

#### 输出

- 预测位置
- 预测到达高度
- 到位时间
- 置信度：高/低

低置信度需要同步激活 M9 异常兜底。

#### 验收标准

- 接球落点不再只跟随接球人当前位置。
- 接球人能提前跑向预测位置。
- 低置信度场景能进入兜底逻辑。

### 5.4 M4：接球人锁定

#### 优先级

P0

#### 需求描述

踢球帧锁定 Top-1 接球人，避免球飞行中 AI 任务重分配导致接球人离开落点。

#### 规则

- Top-1 候选获得“传中锁定”标记。
- 锁定期间，AI 任务分配跳过该球员。
- Top-2/Top-3 保持跑位，作为次选备用。
- 解锁条件：接到球、球被拦截、M9 触发、传中失败。

#### 验收标准

- 接球人在球飞行过程中不会被普通 AI 任务打断。
- 接球人不会突然离开落点。
- 传中结束后锁定状态能正确释放。

### 5.5 M5：落点计算

#### 优先级

P0

#### 需求描述

落点直接取 M3 的预测位置，不再使用前柱-后柱线段投影作为主要逻辑。

#### 规则

- 根据 Top-1 的预测位置计算落点。
- 飞行时间由接球人到位时间反算。
- 若落点 1.5m 内有防守球员，可做最大 1.5m 的微偏。
- 若超出 M6 飞行时间范围，触发 M9。

#### 验收标准

- 球落点稳定靠近接球人未来位置。
- 接球人有足够时间到位。
- 防守压力下允许合理微偏，但不能飞到无人区。

### 5.6 M6：飞行风格映射

#### 优先级

P1

#### 需求描述

将蓄力档位映射为明确的飞行风格和飞行时间范围。

#### 规则

| 档位 | 飞行风格 | 飞行时间 |
| --- | --- | --- |
| 近柱档 | 低弧、快速、短滞空 | `0.6~1.0s` |
| 中路档 | 标准弧、中速 | `0.9~1.4s` |
| 远柱档 | 高弧、中低速、长滞空 | `1.2~1.8s` |

#### 验收标准

- 三档传中弧线视觉差异明显。
- 玩家能通过球速、弧线、滞空时间感知蓄力差异。
- 飞行时间范围能被 M5 使用。

### 5.7 M7：球的飞行

#### 优先级

P0

#### 需求描述

踢球帧一次性生成完整球轨迹。轨迹生成后不允许飞行中修正。

#### 规则

- 输入 M5 落点和 M6 弧线参数。
- 踢球帧生成完整轨迹。
- 飞行中不根据接球人位置实时改轨迹。
- 使用 55% 轨迹机制，微调球到接球人头部高度。
- 微调依赖 M3 预测高度。

#### 验收标准

- 帧同步下轨迹完全确定。
- 球飞行中不会因 AI 状态变化改变轨迹。
- 球能到达与接球动画匹配的高度。

### 5.8 M8：接球人奔跑到位

#### 优先级

P0

#### 需求描述

接球人从踢球帧开始，按 M3 预测路径跑向落点，并提前切入接球准备动作。

#### 规则

| 路径偏差 | 行为 |
| --- | --- |
| `<30°` | 融合修正 |
| `30°~90°` | 转向动画 |
| `>90°` | 触发 M9 |

接球准备动作根据预测高度决定：

- 头球
- 胸接
- 脚接
- 其他扩展动作

#### 验收标准

- 接球人踢球帧后立即开始有效跑动。
- 不再出现明显停步等待。
- 接球动作与球到达高度匹配。

### 5.9 M9：异常兜底

#### 优先级

P0

#### 需求描述

当预测不稳定、路径偏差过大或接球人无法按时到位时，系统按四级策略兜底。

#### 兜底策略

1. 轻微修正：偏差 `<30°`，接球人微调路径。
2. 次选接手：偏差 `30°~90°`，解锁 Top-2 候选。
3. 落点微调：差一点点时微偏，最大 `0.5m`。
4. 传中失败：球落地，进入地面争抢。

#### 验收标准

- 可挽救场景优先挽救。
- 不可挽救场景明确失败，不表现为随机。
- 次选接手逻辑不会破坏帧同步。

### 5.10 M10：守门员出击

#### 优先级

P1

#### 需求描述

守门员出击从“到位时间单维比较”升级为“时差 + 属性博弈”。

#### 判定规则

- 计算接球人到位时间。
- 计算守门员到位时间。
- 得到双方时差。
- 时差大于阈值：守门员直接出击。
- 时差接近 0：进入争顶属性博弈。
- 守门员明显慢：不出击。
- 球轨迹大幅变化：守门员中止出击回位。

#### 属性维度

- 守门员出击能力
- 守门员反应
- 守门员身高
- 接球人头球能力
- 接球人弹跳
- 接球人身体对抗
- 球到达高度

#### 验收标准

- 守门员不再传中出击必胜。
- 高头球、高弹跳前锋可在合理场景赢得争顶。
- 守门员明显更早到位时仍能稳定处理。

### 5.11 M11：玩家实时反馈

#### 优先级

P1

#### 需求描述

玩家按下传中键后，应实时看到候选目标和蓄力档位反馈。

#### 规则

- 按下传中键后，高亮 Top-1 候选，白色光圈。
- 蓄力进入新档位后，光圈颜色变化。
- 近柱档：黄色。
- 中路档：橙色。
- 远柱档：红色。
- 进入新档位时触发振动反馈。
- 松手后播放锁定动效：收缩 + 闪烁。
- 球飞行中保持目标高亮，直到接球或落地。

#### 验收标准

- 玩家松手前能知道大概率传给谁。
- 玩家能感知当前蓄力档位。
- 反馈不遮挡核心比赛视野。

## 6. 非功能需求

### 6.1 帧同步要求

所有新增逻辑必须使用确定性计算。涉及浮点的部分需要使用项目既有定点数方案，避免客户端分歧。

### 6.2 性能要求

候选筛选、未来位置预测、守门员出击判断不能造成明显帧耗增加。

建议：

- 只在传中关键帧执行完整决策。
- Top-3 后续持续跟踪，避免全员每帧重算。
- 复杂预测只对候选人执行。

### 6.3 配置化要求

建议配置项：

- 近柱/中路/远柱蓄力阈值。
- 各档飞行时间范围。
- 各档弧线参数。
- 候选人评分权重。
- 越位软扣分权重。
- 防守微偏半径和最大偏移。
- 路径偏差阈值。
- 守门员出击时差阈值。
- 守门员属性博弈权重。

| 系统 | 影响内容 | 模块 | 影响程度 |
| --- | --- | --- | --- |
| 候选人选人系统 | 动态归属度替换静态区域判定，评分维度重构 | M2 | 高 |
| 接球点计算 | 新增未来位置预测，重写落点计算 | M3、M5 | 高 |

| 帧同步 | 所有新增逻辑必须确定性 | 全部 | 约束 |

## 8. 验收场景

### 8.1 底线短按传中

#### 输入

玩家在底线附近短按传中。

#### 期望

- 近柱球员高亮。
- 低弧快球飞向近柱。
- 接球人提前跑位。
- 接球动作流畅。

### 8.2 底线长按传中

#### 输入

玩家在底线附近长按传中。

#### 期望

- 远柱球员高亮。
- 高弧慢球飞向远柱。
- 滞空感明显。
- 接球人提前到位争顶。

### 8.3 摇杆指定方向传中

#### 输入

玩家蓄力时推动摇杆指向远柱或中路。

#### 期望

候选人排序受摇杆方向明显影响，传中目标符合玩家输入意图。

### 8.4 接球人被防守干扰

#### 输入

接球人预测落点附近有防守球员。

#### 期望

落点可进行合理微偏，但仍在接球人可达范围内。

### 8.5 接球人无法到位

#### 输入

Top-1 接球人路径偏差过大或预测置信度低。

#### 期望

M9 兜底触发，优先次选接手或轻微修正；不可挽救时明确传中失败，进入地面争抢。

### 8.6 守门员出击

#### 输入

传中落点靠近小禁区，守门员有出击机会。

#### 期望

- 守门员明显更早到位时，稳定出击成功。
- 双方接近同时到位时，进入属性博弈。
- 高头球、高弹跳前锋有机会赢得争顶。

### 8.7 帧同步回归

#### 输入

多人对战环境重复播放相同输入。

#### 期望

传中目标、落点、轨迹、接球人选择、守门员出击结果完全一致。

## 9. 风险与对策

### 9.1 风险：传中变得过强

如果接球稳定性和守门员博弈同时增强，传中可能成为过高收益进攻方式。

对策：通过防守评分、落点压力、守门员属性、争顶属性权重调平衡。

### 9.2 风险：候选高亮暴露过多信息

防守方可能通过 UI 提前知道传中目标。

对策：高亮仅本方可见，或对对手隐藏具体目标反馈。

### 9.3 风险：轨迹固定导致无法修正异常

轨迹踢球帧固定后，飞行中无法动态修正，可能在极端场景出现不自然失败。

对策：M9 在踢球帧或早期就完成兜底选择；不可救场景明确传中失败。

### 9.4 风险：接球人锁定影响 AI 行为

锁定接球人可能导致其忽略更优任务。

对策：锁定仅在球飞行期间有效，且设置明确解锁条件。

### 9.5 风险：动画高度覆盖不足

三档高度对应动作不足时，可能出现动作不匹配。

对策：先扩充候选集；不足时按最近高度降级匹配。
