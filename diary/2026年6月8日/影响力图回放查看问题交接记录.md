# 影响力图回放查看问题交接记录

时间：2026年6月8日

## 目标

OpenSpec：`openspec\changes\replay-influence-map-visualization\tasks.md`

目标是在游戏内黑盒回放场景，通过 `AI综合` Debug 面板新增“影响力图回放查看”，支持普通影响力图和直塞中间图查看。

当前状态：

- 普通图显示正常。
- 直塞中间图始终显示无数据。
- 用户验证：切到直塞中间图后再触发直塞，仍不显示。

## 现象

面板显示类似：

```text
直塞中间图 predict_pos 状态：不支持稳定回放或当前无数据
```

Python 诊断日志显示：

```text
[InfMapReplayDebug] name=predict_pos, type=StraightPassInfluenceMap, has_py_cache=False, cpp_gizmos_enabled=True, cpp_keys=[], has_cpp_get=True
```

含义：

- 面板能拿到 map。
- map 类型是 `StraightPassInfluenceMap`。
- C++ `debug_enable_gizmos()` 已启用。
- C++ getter 存在。
- C++ 中间图 key 为空：`cpp_keys=[]`。
- Python `_inter_map_data` 也不存在：`has_py_cache=False`。

## 已知结论

### 1. C++ 断点整局未命中

用户手动在以下 C++ 位置打断点，一整局均未命中：

- `Engine/Sources/External/framecore/external/ai/influence_maps/straight_pass_influence_map.cpp:346`
  - `StraightPassInfluenceMap::py_get_random_straight_pass_position`
- `straight_pass_influence_map.cpp:155`
  - `StraightPassInfluenceMap::get_random_straight_pass_position_by_lp`
- `straight_pass_influence_map.cpp:420`
  - `py_debug_record_intermediate_map("predict_pos")` 调用点
- `straight_pass_influence_map.cpp:998`
  - `StraightPassInfluenceMap::py_debug_record_intermediate_map`

结论：当前测试流程大概率未走 C++ 直塞选点路径，或实际使用 Python 版直塞影响力图实现。

### 2. C++ log 不可靠原因已确认

`fix_ai_util::log` 实现位置：

`Engine/Sources/External/framecore/external/ai/utils.cpp:39`

逻辑：

- 主线程：调用 `framecore_common::engine_log`，进入 `ClientLog`。
- 非主线程：只写 `std::cout`，不一定进入 `ClientLog`。

因此之前 C++ `fix_ai_util::log` 无输出不能证明代码没走；但改成 `framecore_common::engine_log` 后仍没有 `[InfMapReplayDebugCPP]`，并且断点也没命中，因此更支持“没走 C++ 路径”。

### 3. 面板读到的是 C++ wrapper，但计算可能走 Python 实现或未触发

面板诊断中：

```text
type=StraightPassInfluenceMap
has_cpp_get=True
```

说明当前 map 对象有 C++ wrapper 的接口。

但 C++ 计算断点未命中，可能原因：

1. 回放查看面板只读 snapshot，不会重新触发直塞选点计算。
2. 当前测试局没有触发 `Operations/StraightPass.py` 的直塞选点流程。
3. 直塞计算走 Python `StraightPassInfluenceMap.py` 版本，而非 C++。
4. map 实例读写不一致：面板读到 C++ map，计算写到 Python map 或另一个实例。
5. 中间图缓存没有进入 snapshot，回放恢复后天然丢失。

### 9. 对影响力图回放设计的影响

当前“直塞中间图回放查看”设计基于旧假设：

```text
直塞选点会产出 StraightPassInfluenceMap 的 predict_pos 中间图
```

但实际运行链路不是这样。实际运行链路是：

```text
C++ through_pass_operation / Pass::tick cluster 选点
```

因此后续设计需要重新讨论：

1. 如果目标是查看“旧 StraightPassInfluenceMap 中间图”，它可能只适用于旧逻辑或特定开关，不代表当前实战直塞。
2. 如果目标是查看“当前实战直塞选点过程”，应改为捕获 C++ 新 cluster 逻辑的数据：候选点、评分结果、best point、taker、target、travel time 等。
3. 面板命名也应重新评估：不应再叫简单的 `predict_pos` 中间图，可能需要新的数据源/图层，例如 `through_pass_cluster_candidates`、`through_pass_cluster_score`、`through_pass_best_point`。
4. 回放稳定性仍需独立设计：不能依赖 QuickGizmos 临时字段，应将 debug capture 数据纳入可回放 snapshot 或专门的 replay debug 数据源。
