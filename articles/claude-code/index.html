1. 安装与环境配置

1.1 推荐安装方式

Anthropic 官方推荐使用原生安装器，它支持后台自动更新。

macOS / Linux:

curl -fsSL https://claude.ai/install.sh | sh

Windows (PowerShell):

irm https://claude.ai/install.ps1 | iex

1.2 其他安装方式

Homebrew (macOS):

brew install claude-code

# 更新时需手动执行
brew upgrade claude-code

Winget (Windows):

winget install Anthropic.ClaudeCode
注意：npm 安装方式已弃用，请使用上述推荐方式安装。

1.3 验证安装

# 检查版本
claude --version

# 首次运行，进行身份验证
claude

3. 基础使用

3.1 启动会话

# 在当前目录启动
claude

# 指定工作目录
claude --cwd /path/to/project

# 带初始提示启动
claude "分析这个项目的架构"

# 非交互模式（执行后退出）
claude -p "生成 README.md"

3.2 基础对话

> 解释一下 src/auth.ts 的认证逻辑

Claude: 让我阅读这个文件...

[Claude 自动读取并分析代码]

这个文件实现了 JWT 认证流程：
1. validateToken() 验证 token 签名
2. refreshToken() 处理 token 刷新
3. ...

> 添加一个 logout 函数

Claude: 我来添加 logout 函数...

[Claude 编辑文件]

3.3 模型选择

# 使用 Sonnet（默认，更快）
claude --model sonnet

# 使用 Opus（更强大）
claude --model opus

# 会话中切换
> /model opus

4. CLAUDE.md 项目记忆

CLAUDE.md 是 Claude Code 的持久化记忆文件，在每次会话开始时自动加载。

4.1 文件位置优先级

  1. ~/.claude/CLAUDE.md - 全局配置，所有项目生效
  2. ./CLAUDE.md - 项目根目录，当前项目生效
  3. ./.claude/CLAUDE.md - 项目配置目录

4.2 示例内容

# 项目规范

## 技术栈
- Frontend: React 18 + TypeScript + Tailwind CSS
- Backend: Node.js + Express + PostgreSQL
- Testing: Jest + React Testing Library

## 代码风格
- 使用函数式组件和 Hooks
- 组件文件使用 PascalCase 命名
- 工具函数使用 camelCase 命名
- 每个组件需要有对应的 .test.tsx 文件

## 目录结构
```
src/
├── components/    # UI 组件
├── hooks/         # 自定义 Hooks
├── services/      # API 调用
├── utils/         # 工具函数
└── types/         # TypeScript 类型定义
```

## 常用命令
- 运行测试: `npm test`
- 启动开发服务器: `npm run dev`
- 类型检查: `npm run typecheck`

## 注意事项
- 不要修改 .env.production 文件
- 数据库迁移需要先在本地测试
- PR 必须通过所有 CI 检查

5. 配置文件详解

5.1 目录结构

.claude/
├── settings.json        # 主配置（hooks、权限、环境变量）
├── settings.local.json  # 本地配置（gitignore）
├── settings.md          # 配置文档说明
├── agents/              # 自定义 Agent
├── commands/            # 斜杠命令
├── hooks/               # Hook 脚本
└── skills/              # 技能文档

5.2 settings.json 示例

{
  "permissions": {
    "allow": [
      "Read(*)",
      "Glob(*)",
      "Grep(*)",
      "Bash(npm run *)",
      "Bash(git status)",
      "Bash(git diff *)"
    ],
    "deny": [
      "Bash(rm -rf *)",
      "Read(.env*)"
    ]
  },
  "env": {
    "NODE_ENV": "development"
  },
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit",
        "command": "npx prettier --write $CLAUDE_FILE_PATH"
      }
    ]
  }
}

6. 权限控制系统

Claude Code 提供细粒度的权限控制，确保安全操作。

6.1 权限模式

模式 说明 启动参数
Default 敏感操作需确认 默认
Auto-accept 自动接受所有操作 --dangerously-skip-permissions
Plan Mode 只规划不执行 会话中 Shift+Tab+Tab

6.2 权限语法

# 允许所有读取操作
Read(*)

# 允许特定 npm 命令
Bash(npm run *)
Bash(npm test)

# 允许 git 操作（只读）
Bash(git status)
Bash(git log *)
Bash(git diff *)

# 拒绝危险操作
Bash(rm -rf *)
Bash(git push --force *)

# 拒绝读取敏感文件
Read(.env*)
Read(**/secrets/*)

6.3 运行时管理权限

# 查看当前权限
> /permissions

# 添加权限
> /permissions allow Bash(docker *)

# 撤销权限
> /permissions deny Bash(docker *)

7. 斜杠命令

7.1 内置命令

命令 说明
/help 显示帮助信息
/clear 清除对话历史
/compact [指令] 压缩对话上下文
/config 打开配置面板
/permissions 管理权限设置
/model [name] 切换模型
/exit 退出会话

7.2 自定义命令

在 .claude/commands/ 目录创建 Markdown 文件：

# .claude/commands/review.md
---
description: 代码审查
---

请对当前变更进行代码审查，关注以下方面：

1. **代码质量**
   - 命名是否清晰
   - 函数是否过长
   - 是否有重复代码

2. **潜在问题**
   - 边界条件处理
   - 错误处理
   - 性能问题

3. **安全性**
   - 输入验证
   - SQL 注入风险
   - XSS 风险

请用 Markdown 格式输出审查报告。

使用：

> /review

8. Skills 技能系统

Skills 是领域知识文档，帮助 Claude 理解特定技术栈或项目规范。

8.1 创建 Skill

# .claude/skills/testing/SKILL.md
---
description: Jest 测试规范
triggers:
  - keywords: [test, jest, mock, coverage]
  - paths: ["**/*.test.ts", "**/*.spec.ts"]
---

# 测试规范

## 文件命名
- 单元测试: `*.test.ts`
- 集成测试: `*.integration.test.ts`

## 测试结构
```typescript
describe('ComponentName', () => {
  beforeEach(() => {
    // 设置
  });

  it('should do something', () => {
    // Arrange
    // Act
    // Assert
  });
});
```

## Mock 规范
- 使用 `jest.mock()` mock 模块
- 使用 `jest.spyOn()` 监视方法
- 测试后清理: `jest.clearAllMocks()`

## 覆盖率要求
- 语句覆盖率: > 80%
- 分支覆盖率: > 70%

8.2 Skill 触发方式

  • 关键词触发：当对话包含指定关键词时自动激活
  • 路径触发：当操作匹配指定文件路径时激活
  • 手动调用：使用 /skill-name 直接调用

8.3 禁止自动调用

---
description: 部署脚本
disable-model-invocation: true
---

# 部署流程
...

设置 disable-model-invocation: true 后，该 Skill 只能由用户手动调用。

9. Hooks 钩子系统

Hooks 是在特定事件触发时自动执行的 shell 命令。

9.1 Hook 事件类型

事件 触发时机 典型用途
SessionStart 会话开始 环境检查、加载配置
UserPromptSubmit 用户提交提示词 输入验证、技能路由
PreToolUse 工具调用前 权限检查、阻止操作
PostToolUse 工具调用后 代码格式化、日志记录
Stop Claude 停止响应 通知用户

9.2 配置示例

{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit",
        "command": "npx prettier --write \"$CLAUDE_FILE_PATH\""
      },
      {
        "matcher": "Write",
        "command": "npx eslint --fix \"$CLAUDE_FILE_PATH\""
      }
    ],
    "PreToolUse": [
      {
        "matcher": "Bash",
        "command": ".claude/hooks/validate-command.sh"
      }
    ],
    "Stop": [
      {
        "command": "osascript -e 'display notification \"Claude 已完成\" with title \"Claude Code\"'"
      }
    ]
  }
}

9.3 Hook 脚本示例

#!/bin/bash
# .claude/hooks/validate-command.sh

# 读取 Claude 要执行的命令
COMMAND="$CLAUDE_BASH_COMMAND"

# 检查危险命令
if [[ "$COMMAND" == *"rm -rf"* ]]; then
    echo "blocked: 不允许执行 rm -rf 命令"
    exit 1
fi

if [[ "$COMMAND" == *"--force"* ]]; then
    echo "blocked: 不允许使用 --force 参数"
    exit 1
fi

exit 0
提示：Hook 输出 "blocked:" 前缀会阻止操作并将消息反馈给 Claude。

10. MCP 服务器扩展

MCP (Model Context Protocol) 允许扩展 Claude Code 的能力。

10.1 配置 MCP 服务器

# 添加项目级 MCP 服务器
claude mcp add my-server --scope project

# 添加用户级 MCP 服务器
claude mcp add my-server --scope user

# 查看已配置的服务器
claude mcp list

10.2 .mcp.json 示例

{
  "mcpServers": {
    "memory": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-memory"],
      "env": {
        "MEMORY_FILE_PATH": ".claude/memory.json"
      }
    },
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@anthropic/mcp-server-filesystem"],
      "env": {
        "ALLOWED_PATHS": "/home/user/projects"
      }
    },
    "github": {
      "command": "npx",
      "args": ["-y", "@anthropic/mcp-server-github"],
      "env": {
        "GITHUB_TOKEN": "${GITHUB_TOKEN}"
      }
    }
  }
}

10.3 常用 MCP 服务器

  • memory: 跨会话持久化记忆
  • filesystem: 文件系统操作增强
  • github: GitHub API 集成
  • postgres: 数据库操作
  • puppeteer: 浏览器自动化

12. 最佳实践

12.1 项目配置

  1. 从 CLAUDE.md 开始：保持简洁但完整，包含技术栈、代码规范、重要约定
  2. 增量构建 Skills：针对高频场景（如测试、代码审查）创建专门的 Skill
  3. 使用 Hooks 自动化：避免手动执行格式化、lint 等重复任务
  4. 版本控制配置：提交所有配置文件，但 gitignore 本地覆盖

12.2 安全建议

  • 不要在配置文件中硬编码密钥，使用环境变量
  • 配置权限规则拒绝危险操作
  • 使用 Read(.env*) 保护敏感配置文件
  • 定期审查 .claude/settings.json 的权限配置

12.3 效率技巧

  • 使用 /compact 压缩长对话，保留关键上下文
  • 为常用工作流创建斜杠命令
  • 使用 --model opus 处理复杂任务
  • 配置通知 Hook，长任务完成时提醒

12.4 团队协作

  • 统一 CLAUDE.md 模板，确保团队成员使用一致的规范
  • 共享 Skills 和 Commands 配置
  • 使用 settings.local.json 存储个人偏好
  • 在 CI 中集成 Claude Code 进行自动化代码审查
