## 开场

上期我们学会了怎么安装和启动Claude Code。

但很多人用了一段时间后会发现：有时候Claude表现很好，有时候又乱来。

问题往往出在——**你没选对模式**。

今天我们聊聊Claude Code的三种工作模式，理解它们是高效使用的关键。

## 模式一：正常模式（默认）

这是你启动Claude Code后的默认状态。

**特点**：直接告诉它你要什么，它就去做。

```
给这个函数加个参数校验
```

它会分析代码、写修改、每一步都问你"可以吗？"

**适合场景**：

- 日常开发
- 小改动
- 明确知道要做什么

**缺点**：面对复杂任务，它可能会冲动行事，走弯路。

## 模式二：计划模式（Plan Mode）

按 `Shift+Tab` 切换。

**特点**：Claude不会立刻动手写代码，而是先跟你讨论方案。

```
我想重构整个认证模块，有什么方案？
```

它会列出几种可能的方案，和你讨论优缺点，达成共识后再动手。

**适合场景**：

- 大功能开发
- 代码重构
- 架构决策
- 任何你不确定怎么做的事

> **黄金法则**：规划的时间花得越多，Claude成功的概率越高。

这是我最想强调的一点。很多人上来就让Claude写代码，结果写了一堆废物。先进计划模式，把方案聊清楚，再动手。

## 模式三：危险模式（Yolo Mode）

启动时加参数：

```
claude --dangerously-skip-permissions
```

**特点**：Claude不再每一步都问"可以吗？"，直接干活。

**适合场景**：

- 你完全信任它
- 有Git可以回滚
- 想要极致速度

**警告**：这就像把车钥匙交给一个刚拿驾照的人。速度快，但请确保你有安全网。

## 三种模式对比

| 模式 | 触发方式 | 特点 | 适合场景 |
| --- | --- | --- | --- |
| 正常 | 默认 | 边做边问 | 小改动、日常开发 |
| 计划 | Shift+Tab | 先讨论后动手 | 大功能、重构、不确定的事 |
| 危险 | --dangerously-skip-permissions | 不问直接做 | 完全信任、有备份 |

## 实战建议

### 新功能开发的标准流程

1. **先进计划模式**（Shift+Tab）
2. 说："我想实现XXX功能，有什么方案？"
3. 让Claude探索，从最简单的方案开始
4. 确定方案后，让它写个spec文档
5. 再切回正常模式，逐步实现

### 我的经验

我现在养成了一个习惯：**任何超过10行代码的改动，先进计划模式聊两句**。

这个习惯帮我省了无数推倒重来的时间。

## 小结

今天我们学了三种模式：

1. **正常模式**：小活直接干
2. **计划模式**：大事先商量
3. **危险模式**：完全放手（谨慎使用）

记住那个黄金法则：**规划的时间花得越多，成功率越高**。
